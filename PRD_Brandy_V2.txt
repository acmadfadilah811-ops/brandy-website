BAGIAN 3: SISTEM ADMIN PANEL (CMS TANPA KODE)
================================================================================
Tujuan: Owner dapat mengubah SEMUA konten website tanpa menyentuh kode.

3.1 AUTENTIKASI ADMIN
  - Login via Supabase Auth (email + password)
  - JWT Token disimpan di httpOnly Cookie (BUKAN localStorage)
  - Session timeout: 8 jam, auto-refresh jika aktif
  - Rate limiting login: maksimal 5 percobaan gagal → lockout 15 menit
  - WAJIB: Password hashing menggunakan bcrypt (sudah ditangani Supabase)
  - WAJIB: CSRF Protection pada semua form POST
  - WAJIB: Route /admin/* dilindungi middleware Next.js (middleware.ts)

3.2 MODUL CMS YANG HARUS TERSEDIA DI ADMIN PANEL
  a) Pengaturan Global (Settings)
     - Nama perusahaan, tagline, email kontak, nomor WhatsApp, alamat kantor
     - Upload logo (header & footer), favicon
     - Tautan media sosial (LinkedIn, Twitter, Instagram)
     - Google Maps embed URL
     
  b) Manajemen Blog
     - Buat, edit, hapus artikel blog
     - Upload gambar thumbnail dan cover
     - Rich text editor (WYSIWYG) — gunakan TipTap atau Sanity Portable Text
     - Pilih kategori, tag, dan status (Draft / Published)
     - Set penulis (Author) dari daftar tim
     
  c) Manajemen Produk
     - Edit nama, deskripsi, tagline, harga, fitur tiap produk SaaS
     - Upload gambar/icon produk
     - Edit ROI metrics dan data integrations
     
  d) Manajemen Tim & About
     - Edit profil anggota tim (nama, jabatan, foto, bio, LinkedIn)
     - Edit Timeline milestones perusahaan (tahun, judul, deskripsi)
     - Edit Core Values (B-R-A-N-D-Y): judul dan deskripsi tiap poin
     - Edit teks Misi dan Visi
     
  e) Manajemen Harga (Pricing)
     - Edit nama paket, harga bulanan/tahunan, deskripsi
     - Edit daftar fitur tiap paket (included / not included)
     - Tambah/hapus baris tabel perbandingan fitur
     - Edit FAQ pricing
     
  f) Manajemen Karir (Careers)
     - Buat, edit, hapus lowongan kerja
     - Set departemen, lokasi, tipe (remote/hybrid/full-time)

  g) Manajemen Integrasi
     - Tambah/hapus konektor tool (nama, logo, kategori, deskripsi)
     
  h) Manajemen Pelanggan (Customers/Testimonials)

3.3 PROTEKSI DATA DI ADMIN PANEL
  - Semua endpoint /api/admin/* WAJIB memvalidasi JWT sebelum proses apapun
  - Input sanitization wajib pada semua field teks (cegah XSS)
  - File upload: validasi tipe (hanya jpg/png/webp/svg/pdf) + max size 5MB
  - SQL injection: gunakan Supabase query builder (parameterized queries)

BAGIAN 4: SISTEM CACHING & PERFORMA
================================================================================
4.1 STRATEGI CACHE NEXT.JS (App Router)

  a) Halaman Statis (SSG) — cache penuh di CDN:
     - /about, /legal/privacy, /legal/terms
     - Gunakan: export const revalidate = 3600 (refresh tiap 1 jam)

  b) Halaman Semi-Dinamis (ISR) — stale-while-revalidate:
     - /blog, /blog/[slug], /products, /products/[slug], /customers, /integrations
     - Gunakan: export const revalidate = 300 (refresh tiap 5 menit)
     - On-demand revalidation dari Admin Panel saat konten diperbarui

  c) Halaman Interaktif (Client-Side):
     - /pricing, /demo, /contact, /careers — rendered client-side
     - Data statis di-prefetch via React Query atau SWR

  d) Route API Cache:
     - GET /api/blog → cache: max-age=300, stale-while-revalidate=600
     - GET /api/settings → cache: max-age=3600
     - POST /api/* → NO cache (cache-control: no-store)

4.2 HTTP CACHE HEADERS (Wajib di next.config.ts)
  - Aset statis (/public/*): Cache-Control: public, max-age=31536000, immutable
  - Font Google: preloaded via <link rel="preload"> di layout.tsx
  - Gambar: gunakan Next.js <Image> dengan priority={true} untuk above-fold

4.3 CLIENT-SIDE CACHING
  - Gunakan SWR atau React Query untuk fetching data di komponen client
  - Default SWR config: dedupingInterval=60000, revalidateOnFocus=false
  - LocalStorage: HANYA untuk preferensi UI non-sensitif (misal: tema gelap)
  - JANGAN simpan token auth atau data user di localStorage

BAGIAN 5: STANDAR KEAMANAN (SECURITY)
================================================================================
5.1 AUTENTIKASI & SESI
  - Auth provider: Supabase Auth (sudah battle-tested, SOC2 compliant)
  - Token: JWT disimpan di httpOnly, Secure, SameSite=Strict Cookie
  - Refresh token rotation aktif
  - Logout: invalidate semua sesi aktif di Supabase

5.2 HTTP SECURITY HEADERS (Wajib di next.config.ts)
  Tambahkan headers berikut untuk semua response:
    Content-Security-Policy (CSP): default-src 'self'; script-src 'self' 'unsafe-inline' 
      https://www.googletagmanager.com; img-src 'self' data: https:; 
      connect-src 'self' https://*.supabase.co https://*.sanity.io
    X-Frame-Options: DENY
    X-Content-Type-Options: nosniff
    Referrer-Policy: strict-origin-when-cross-origin
    Permissions-Policy: camera=(), microphone=(), geolocation=()
    Strict-Transport-Security: max-age=63072000; includeSubDomains; preload

5.3 INPUT VALIDATION
  - Gunakan library Zod untuk validasi semua input form di server-side
  - Sanitasi HTML: gunakan DOMPurify sebelum render konten CMS ke halaman publik
  - File upload: validasi MIME type di server (jangan percaya ekstensi file saja)
  - Rate limiting API: gunakan middleware Upstash Redis atau Vercel Edge

5.4 ENVIRONMENT VARIABLES
  - SEMUA secret key (Supabase, Sanity, dll.) WAJIB di .env.local
  - JANGAN commit .env ke git — pastikan .gitignore mencakupnya
  - Variabel publik (diakses browser): prefix NEXT_PUBLIC_
  - Variabel privat (server-only): tanpa prefix, akses hanya di Server Components/API

5.5 PROTEKSI ROUTE ADMIN
  File: src/middleware.ts
  Logic: Cek cookie JWT di setiap request ke /admin/*
  Jika tidak valid → redirect ke /admin/login
  Jangan pernah expose error detail ke response publik (gunakan log server)

BAGIAN 11: PANDUAN DESAIN LANJUTAN — FUNGSIONAL & ESTETIKA
================================================================================
Bagian ini adalah panduan desain mendalam yang WAJIB diikuti AI saat membangun
atau memodifikasi halaman apapun. Tujuannya adalah memastikan setiap keputusan
desain memiliki dasar fungsional (membantu user mencapai tujuan) sekaligus
estetika (memberi kesan premium, profesional, dan terpercaya).

11.1 PRINSIP DASAR DESAIN BRANDY
--------------------------------------------------------------------------------
Empat pilar utama yang harus ada di setiap komponen dan halaman:

  [P1] CLARITY (Kejelasan)
       Pengguna harus tahu dalam 3 detik pertama: "ini website apa, untuk siapa,
       dan apa yang bisa saya lakukan di sini." Setiap elemen UI harus memiliki
       tujuan yang jelas. Hapus elemen dekoratif yang tidak menambah nilai.

  [P2] HIERARCHY (Hierarki Visual)
       Mata pengguna harus bergerak secara natural dari elemen terpenting ke
       elemen pendukung. Gunakan ukuran, warna, dan bobot font untuk menciptakan
       urutan baca yang intuitif. Hero → Section Title → Body → CTA.

  [P3] CONSISTENCY (Konsistensi)
       Komponen yang sama harus terlihat dan berperilaku sama di seluruh halaman.
       Jarak, warna, border-radius, dan animasi tidak boleh berbeda antar halaman
       kecuali ada alasan desain yang eksplisit tercatat di PRD ini.

  [P4] DELIGHT (Kesenangan)
       Detail kecil yang membuat pengguna tersenyum: animasi hover yang halus,
       transisi yang mulus, pesan sukses yang ramah, loading state yang elegan.
       Ini yang membedakan produk biasa dari produk premium.

11.2 HIERARKI VISUAL & WHITESPACE
--------------------------------------------------------------------------------
Whitespace (ruang kosong) adalah elemen desain, bukan pemborosan ruang.

  Aturan Whitespace:
  - Gunakan section padding py-20 (80px) secara konsisten antar section
  - Gap antar card dalam grid: gap-8 (32px) standar, gap-6 (24px) untuk grid padat
  - Padding dalam card: p-8 (32px) untuk card besar, p-6 (24px) untuk card standar
  - Jarak antara heading dan body text: mb-4 (16px)
  - Jarak antara section label (badge) dan heading: mb-4 (16px)
  - Jarak antara body text dan CTA button: mb-8 (32px)

  Hierarki Ukuran Font dalam Satu Section:
    1. Badge label          → text-xs uppercase tracking-widest (paling kecil, di atas)
    2. Section heading      → text-heading-xl font-bold (dominan)
    3. Section description  → text-body-md text-slate-500 (pendukung, max 2 baris)
    4. Card title           → text-base atau text-lg font-bold
    5. Card description     → text-sm text-slate-600
    6. Caption/label kecil  → text-xs text-slate-400

  Aturan Kontras Warna Teks (WCAG AA Minimum):
  - Teks gelap di background putih : slate-900 atau slate-800 ✓
  - Teks sekunder di background putih: slate-600 (ratio > 4.5:1) ✓
  - Teks putih di background gelap  : white atau slate-200 ✓
  - JANGAN gunakan slate-400 sebagai teks utama di background putih ✗
  - JANGAN gunakan teks warna brand langsung untuk body text panjang ✗

11.3 SISTEM GRID & LAYOUT RESPONSIF
--------------------------------------------------------------------------------
Semua layout WAJIB responsif (mobile-first). Gunakan pola grid berikut:

  Pola Grid Standar:
    - 1 kolom  (mobile  < 768px)  → grid-cols-1
    - 2 kolom  (tablet 768-1024px) → md:grid-cols-2
    - 3 kolom  (desktop > 1024px) → lg:grid-cols-3
    - 4 kolom  (wide > 1280px)    → xl:grid-cols-4

  Layout Section Khusus:
    - Hero             : full-width, max konten 4xl (896px), center-aligned
    - Feature Bento    : grid asimetris (1 besar + 2 kecil, atau 2+2+1)
    - 50/50 Layout     : lg:grid-cols-2 dengan gap-12, items-center
    - Narrow Content   : max-w-2xl atau max-w-3xl, mx-auto (untuk artikel/legal)
    - Sidebar Layout   : lg:grid-cols-12, main lg:col-span-8, aside lg:col-span-4

  Breakpoint Rules:
    - Semua teks heading WAJIB lebih kecil di mobile:
      * text-heading-2xl → mobile: text-3xl atau text-4xl
      * text-heading-xl  → mobile: text-2xl
    - Padding container: px-4 (mobile) → px-6 (tablet) → px-8 (desktop)
    - Stack vertikal di mobile, horizontal di desktop (flex-col → lg:flex-row)

11.8 MICRO-INTERACTIONS & MOTION DESIGN
--------------------------------------------------------------------------------
Animasi yang didefinisikan harus konsisten di seluruh codebase.

  Keyframes Wajib (definisikan di globals.css atau tailwind.config.js):

  @keyframes fade-in:
    from: { opacity: 0; transform: translateY(8px); }
    to  : { opacity: 1; transform: translateY(0); }
    Durasi: 300ms, easing: ease-out
    Gunakan untuk: konten yang muncul setelah interaksi (modal, dropdown, tab)

  @keyframes float:
    0%, 100%: { transform: translateY(0px); }
    50%      : { transform: translateY(-8px); }
    Durasi: 3s, easing: ease-in-out, loop infinite
    Gunakan untuk: elemen dekoratif di hero (ikon produk mengambang)

  @keyframes slide-in-right:
    from: { transform: translateX(100%); }
    to  : { transform: translateX(0); }
    Durasi: 300ms, easing: ease-out
    Gunakan untuk: mobile menu drawer

  @keyframes pulse-glow:
    0%, 100%: { box-shadow: 0 0 0 0 rgba(37, 99, 235, 0.4); }
    50%      : { box-shadow: 0 0 0 8px rgba(37, 99, 235, 0); }
    Durasi: 2s, loop infinite
    Gunakan untuk: tombol CTA utama di hero (opsional, tidak berlebihan)

  Aturan Animasi:
    - JANGAN animasikan lebih dari 1-2 property sekaligus
    - JANGAN gunakan animasi bounce yang berlebihan
    - Semua animasi WAJIB berhenti jika @media (prefers-reduced-motion: reduce)
    - Loading skeleton: bg-slate-200 animate-pulse rounded (untuk placeholder konten)

11.9 LOADING STATES & EMPTY STATES
--------------------------------------------------------------------------------
Setiap halaman yang memuat data asinkron HARUS memiliki loading state.

  Skeleton Loading (untuk card/list):
    - Gunakan div dengan bg-slate-200 animate-pulse
    - Bentuk sesuai konten yang akan muncul (rectangle untuk teks, circle untuk avatar)
    - Jangan gunakan spinner tunggal untuk seluruh halaman kecuali initial page load

  Empty State (saat tidak ada data):
    - Tampilkan ikon besar (48-64px, text-slate-300)
    - Judul: "Belum ada [nama konten]" — text-lg font-bold text-slate-700
    - Deskripsi: 1 kalimat panduan — text-sm text-slate-500
    - CTA: tombol untuk menambah konten baru (di admin) atau kembali (di publik)

  Error State:
    - Ikon warning atau X dalam lingkaran merah muda
    - Pesan error yang ramah (jangan tampilkan stack trace ke user)
    - Tombol "Coba Lagi" untuk retry request

  Success State (setelah submit form):
    - Ikon centang dalam lingkaran hijau
    - Pesan konfirmasi positif (contoh: "Lamaran berhasil terkirim!")
    - Auto-dismiss setelah 3-5 detik atau tombol "Tutup"

11.10 AKSESIBILITAS (A11Y) — STANDAR WAJIB
--------------------------------------------------------------------------------
Website Brandy harus dapat digunakan oleh semua orang, termasuk pengguna
yang menggunakan screen reader atau navigasi keyboard.

  Aturan Wajib:
  - Semua gambar WAJIB memiliki atribut alt yang deskriptif
    * Logo   : alt="Brandy Logo"
    * Foto tim: alt="Nama lengkap anggota tim"
    * Gambar dekoratif: alt="" (string kosong) + aria-hidden="true"
  - Semua tombol WAJIB memiliki teks yang bermakna atau aria-label
  - Semua form input WAJIB memiliki <label> yang terhubung via htmlFor/id
  - Urutan heading WAJIB hierarkis: h1 → h2 → h3 (jangan skip level)
  - Focus visible: JANGAN hilangkan outline focus tanpa menggantinya
    Gunakan: focus-visible:ring-2 focus-visible:ring-brand-blue-mid
  - Warna TIDAK boleh menjadi satu-satunya cara menyampaikan informasi
    (selalu tambahkan ikon atau teks pendamping)
  - Navigasi keyboard: modal, dropdown, dan accordion harus bisa dikontrol
    dengan Tab, Enter, dan Escape
  - ARIA roles: gunakan role="dialog" untuk modal, role="navigation" untuk nav,
    aria-expanded untuk accordion/dropdown, aria-label untuk section penting

11.11 PANDUAN PENGGUNAAN GAMBAR & MEDIA
--------------------------------------------------------------------------------
  - SELALU gunakan komponen <Image> dari next/image (BUKAN <img> HTML biasa)

  - Gambar above-the-fold: tambahkan priority={true}
  - Gambar below-the-fold: biarkan lazy-load default
  - Format gambar: WebP/AVIF diutamakan (Next.js otomatis convert via domains)
  - Thumbnail blog: rasio 16:9, resolusi minimal 800x450px
  - Foto tim: rasio 3:4 (vertikal), resolusi minimal 300x400px
  - Logo: format PNG dengan background transparan
  - Video embed: gunakan <iframe> dengan aspect-ratio 16:9 di dalam container relatif

  Placeholder saat gambar belum ada:
  - Avatar/foto tim: div dengan inisial nama, bg gradient brand colors
  - Thumbnail artikel: div dengan bg-slate-200 + ikon foto di tengah
